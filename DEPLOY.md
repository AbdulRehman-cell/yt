# Deploy Guide (Render) — Under 5 Minutes

This app is a Node.js/Express server (`server/index.js`) using MongoDB, serving a built client (`client/`), containerized via a multi-stage `Dockerfile`.

## Prerequisites

- A [Render](https://render.com) account
- A MongoDB connection string (use [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register) free tier — Render has no native managed MongoDB)
- This repo pushed to GitHub/GitLab

## Option A: One-click via `render.yaml` (Blueprint)

1. Push this repo to GitHub.
2. In Render dashboard: **New +** → **Blueprint** → select your repo. Render auto-detects `render.yaml`.
3. When prompted, set these environment variables:
   - `MONGO_URI` — your MongoDB Atlas connection string
   - `CORS_ORIGIN` — your Render URL, e.g. `https://yt-app.onrender.com`
   - `JWT_SECRET` — auto-generated by Render (already configured)
4. Click **Apply** — Render builds the Docker image and deploys.

That's it. Render will build from the `Dockerfile`, run health checks against `/api/health`, and expose your service.

## Option B: Manual CLI-style deploy (exact commands)

```bash
# 1. Verify the Docker build works locally first
docker build -t yt-app:local .

# 2. Test locally with docker-compose (includes local MongoDB)
cp .env.example .env
# edit .env and set MONGO_ROOT_PASSWORD, JWT_SECRET, etc.
docker compose up --build

# 3. Push to your git remote — Render auto-deploys on push if connected
git add . && git commit -m "Deploy to Render" && git push origin main
```

Then in Render dashboard:
1. **New +** → **Web Service** → connect your repo.
2. Environment: **Docker** (auto-detected from `Dockerfile`).
3. Add env vars from `.env.example` (`MONGO_URI`, `CORS_ORIGIN`, `JWT_SECRET`).
4. Set **Health Check Path** to `/api/health`.
5. Click **Create Web Service**.

## Enabling CI/CD auto-deploy (GitHub Actions)

1. In Render, go to your service → **Settings** → copy the **Deploy Hook URL**.
2. In GitHub repo → **Settings** → **Secrets and variables** → **Actions** → add secret:
   - Name: `RENDER_DEPLOY_HOOK_URL`
   - Value: (paste the hook URL)
3. Every push to `main` will now build, test, and trigger a Render deploy automatically via `.github/workflows/deploy.yml`.

## Verifying deployment

```bash
curl https://<your-service>.onrender.com/api/health
# Expect: {"status":"ok"} or HTTP 200
```

## Notes / Assumptions

- Assumes your Express app exposes a `GET /api/health` route returning HTTP 200. **Add this route if it doesn't exist yet:**
  ```js
  app.get('/api/health', (req, res) => res.status(200).json({ status: 'ok' }));
  ```
- Assumes client build output is `client/dist` (Vite default). If using Create React App, change `client/dist` → `client/build` in the `Dockerfile`.
- MongoDB is external (Atlas) in production; `docker-compose.yml` only spins up local Mongo for development/testing.
